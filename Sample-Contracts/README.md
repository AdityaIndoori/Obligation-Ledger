# Sample contracts for testing

Ten PDFs, all with real text layers except `08` (deliberately none). Drop them
on the **Intake** box at `http://10.10.0.2:8443/`, or copy into
`/srv/ledger/intake`.

Generated by `Code/make_samples.py`. Replay fixtures for all of them are built
by `Code/sample_fixtures.py`, which `demo_reset.sh` runs automatically — so they
extract before vLLM is serving. Every fixture's `source_span` is located as a
real substring of the parsed document, so the validators do genuine work rather
than rubber-stamping.

## Expected behaviour

```
$ python ingest.py Sample-Contracts/*.pdf
OK      01 … 07, 09, 10      fmt=pdf, chars>0
REFUSED 08                   no text layer (scanned image?) -- OCR is out of scope
```

`08` produces a `REJECTED` contract row carrying the reason, and appears under
the **Rejected** heading in the queue — not as a silent empty extraction.

## A note on OCR

OCR is out of scope for the build window (master doc §1.7), but **not because
the models can't do it**: `Qwen3.6-35B-A3B` declares a full `vision_config`
(27-layer encoder) and is a vision-language model. The `gpt-oss` models are
text-only.

The architecturally interesting reason is that OCR inserts a second error source
*upstream of the validators*. V1 checks a quote against the document text; if
that text is itself an OCR guess, "verbatim quote" degrades from "quoted from
the document" to "quoted from a transcription of the document". Shipping OCR
honestly means stamping `text_source=ocr` on the contract and saying so in the
UI. Deferred, not impossible.
